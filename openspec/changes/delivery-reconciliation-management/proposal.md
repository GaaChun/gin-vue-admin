# Proposal

## Why

当前项目只有框架通用能力，尚无物料资料、送货单和对账报表业务。需要先形成可供较小规模 LLM 逐项实施的明确契约，再交付支持日常录入、审核和对账的最小业务闭环。

## What Changes

- 新增单位、品牌、树形类别、物料及多单位维护，支持 Excel 新增/更新导入和导出，物料图片限制为 JPEG/PNG/JPG/BMP 且不超过 1 MiB。
- 新增送货单主从表、正式编号预占、键盘连续录入、多选物料弹窗、审核/反审核、软删除及 Excel 整单更新。整单只允许同一品牌，已审核单禁止编辑和删除。
- 新增仅针对已审核送货单的对账报表。所选显示维度决定分组，统一驱动列表、全量导出、打印和统计；保留单据历史快照，不因基础资料改名而重写历史。
- 新增个人/共享报表方案、系统可配置菜单和操作权限。业务记录具有审计字段及可选乐观锁版本。
- 本轮仅生成中文规划和必要的需求记忆，不生成业务代码，不建业务表，不写入菜单、API 或角色授权。后续实施验证限定为单元测试，不连接浏览器、不做端到端验证。

## Capabilities

### New Capabilities

- `business-record-governance`：业务审计、软删除、可选版本校验、引用保护、菜单及操作权限边界。
- `material-master-data`：单位、品牌、类别树、物料、多单位、图片以及基础资料 Excel 契约。
- `delivery-notes`：编号预占、同品牌主从单据、数值与快照、审核状态、连续录入、送货单 Excel 契约。
- `delivery-reconciliation`：已审核单据投影、显示列驱动的分组聚合、个人/共享方案、导出和打印。

### Modified Capabilities

无。`openspec list --specs --json` 返回空能力清单。

## Impact

### 现有项目依据

- 后端沿用 `Router -> API -> Service -> Model`，复用 GORM、统一响应和 `excelize`。
- `global.GVA_MODEL` 只有 ID、创建/修改时间及软删除时间，必须补齐业务操作者、审核人/时间和版本字段。
- 通用 Excel 导入直接执行字段映射/SQL，不自动经过业务校验；不得直接用于本业务写入。
- 前端沿用 Vue 3、Element Plus、Pinia、框架动态菜单、`@/utils/request` 和标准页面样式。
- 现有上传组件会压缩超限图片且不支持 BMP，不能直接满足本次上传契约。

### 拟新增位置

采用独立业务插件 `warehouse`，后端位于 `server/plugin/warehouse/`，前端位于 `web/src/plugin/warehouse/`。只在现有插件注册入口接入，不改写框架系统模块。详细文件职责、字段、API、Excel 模板、聚合实例和测试矩阵见 [design.md](design.md) 与 [tasks.md](tasks.md)。

### 明确排除

不做库存台账、采购/销售/出入库单、仓库和供应商资料、应收应付结算、税费、币种换算、负数退货、独立分组配置、冻结列、高级筛选配置、公式编辑、异步导出或报表预计算表。参考图片只借鉴已确认的交互及统计逻辑，不照搬其额外业务字段。

### 依赖与验证边界

实施时使用已安装的 OpenSpec Skills 和 GVA MCP，代码生成后使用 `gva_review`。中文拼音首字母、精确十进制及 Vue 组件单元测试可能需要新增小型依赖，由设计规定用途。后端以当前 MySQL 配置为上线目标；单元测试不得连接运行中的数据库、Redis、OSS 或浏览器。当前没有执行任何业务验证，也不把规划完整视为功能已实现。
