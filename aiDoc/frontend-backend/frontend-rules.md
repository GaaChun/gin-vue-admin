# 前端约束

## 基础约束

- HTTP 请求统一走 `@/utils/request.js`
- 全局状态统一使用 Pinia
- 路由要带完整的元信息并考虑权限
- 需要动态路由时，沿用项目现有异步路由处理方式

## 命名规范

- 文件名使用 `kebab-case`
- 组件名使用 `PascalCase`
- 变量名使用 `camelCase`
- 常量名使用 `UPPER_SNAKE_CASE`

## 注释规范

- API 封装尽量补全 JSDoc
- 复杂组件要写清功能说明
- 关键业务逻辑可以补充必要的行内注释

## 样式规范

- 优先使用 UnoCSS
- 遵循 Element Plus 现有设计风格
- 避免内联样式
- 主题相关能力优先通过 CSS 变量控制

## 性能规范

- 路由优先懒加载
- 大列表考虑虚拟滚动或等价优化
- 合理复用缓存
- 图片上传与展示考虑压缩与加载成本

## 编辑页与标签状态

- 独立编辑页保存成功留在当前页；首次保存后使用服务端真实 ID 和版本继续更新，不能重复创建。返回列表、取消和继续新增仍由显式操作触发。
- 布局按完整路由身份缓存打开的标签，列表、新建及不同记录各自隔离，不依赖 `keepAliveTabs` 偏好；每个缓存实例注入独立路由快照，失活页不响应其他标签的查询参数变化。
- 关闭标签清理对应实例，账号或登录态变化清理缓存；切换标签保留编辑内容和列表查询条件。
- 公告的真实列表编辑抽屉保存后保持打开，首次创建后切换为更新；`POST /info/createInfo` 成功响应的 `data` 返回真实公告记录（含 `ID`），独立公告编辑页沿用同一身份契约。
