## 影响范围

- 基础资料：单位、品牌、类别树、物料、多单位、严格图片和Excel。
- 仓库管理：送货单主从、编号、审核/反审核、连续录入和Excel。
- 报表管理：只针对送货单的动态列汇总、个人/共享方案、Excel和打印。
- 系统接入：可配置菜单、角色API/按钮权限及审计字段。
- 采用 warehouse 业务插件；页面必须能够直接作为动态菜单挂载，不能依赖未提供的 loader props。

## 已确认约束

- 对账按所选维度组合分组，只纳入未删除的已审核单；历史字段使用单据快照。
- 每个物料指定唯一启用基本单位，系数1；明细单位必选。箱等辅助单位系数表示对应基本单位数量。
- 仅送货单审核，审核后禁止编辑/删除，反审核后恢复。基础资料只保留审核字段。
- 新建页面预占正式号：SK+业务当日YYMMDD+六位日流水，允许断号，保存后不变。
- 整单品牌一致，修改品牌需确认清空明细，取消则保留。
- 资料各自编号全局唯一；单位名/品牌名全局唯一，类别名同级唯一，物料名可重复。有效引用阻止删除，根类别使用虚拟“无上级”。用户明确修改了推荐选项：软删除资料不占用编号。
- Excel允许更新，整文件事务回滚；单位按名称、资料按编号、单据按正式单号定位；明细和物料单位以完整集合更新。未知非空送货单号不得创建新单，空号分组新单由系统编号。
- 数量4位、单价4位、系数6位、金额2位。数量/系数大于0，单价必填且可为0；先逐行四舍五入再汇总，不处理税费或负数退货。
- 版本号可省略，传入则必须匹配；标准页面始终传版本。编辑/删除/审核/反审核成功递增。
- Enter/Tab提交才移焦，选择确认后移焦；支持多选物料弹窗，不照搬仓库/库存等无关参考图字段。
- 报表采用精简列与金额指标；异物料/单位数量不直接相加，混合单价不相加。方案支持个人与共享两类。
- 用户已授权实施及本轮整改；本轮优先列表与符合文档的报表，只做必要冒烟检查，修改后由用户验收。

## 送货单角色权限修复

- 用户反馈送货页提示“权限不足”且新建按钮不可用，当前配置角色为“仓库管理”。核对数据库确认其角色 ID 为 `1`。
- 缺失的是三个 API 权限记录及授权：`GET /warehouse/master/categories/list`、`GET /warehouse/master/materials/detail`、`GET /warehouse/delivery/detail`。类别列表加载失败会令前端 `optionsReady` 保持 false，从而禁用新建按钮。
- 已补齐三个 API 记录，并仅给角色 `1` 追加这三个 GET 权限，未覆盖原有授权、未变更其他角色。MCP 令牌失效，本次通过项目数据库连接与 Casbin AddPolicy 完成定向修复。
- 新进程重新读取数据库后，送货页依赖的9项接口均为已登记、Casbin允许；随后调用运行后端的 `GET /api/freshCasbin` 返回 `code:0`、“刷新成功”。用户刷新页面即可重新加载；本轮未代用户创建业务单据。
- 品牌新建调用助记符再次提示权限不足：核对 `POST /warehouse/master/mnemonic` 在权限表中也未登记（修复前数量0），角色 `1` 判定拒绝。已登记为“生成助记符建议”（API ID `219`），仅给“仓库管理”角色追加该 POST 权限。重新加载策略后判定允许，运行服务权限缓存刷新返回 `code:0`；未更改其他角色或现有授权。
- 用户随后反馈送货页出现 HTTP 404 通用提示。核对源码与运行后端：送货单8项方法及物料详情/类别列表均可匹配路由（未认证探测返回401），经前端代理的送货列表/预占也能匹配；新增报表及方案接口仍404，说明当前进程尚未加载该部分代码，但不能据此归因用户的具体送货请求。最新后端构建通过；用户明确选择“暂不重启”，保持现有服务，等待其提供实际失败请求URL与HTTP方法后继续定位。
